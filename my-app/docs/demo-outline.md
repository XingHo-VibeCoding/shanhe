## 第一段：用户问题（约 30 秒）

**说什么**：想查一首古诗时，网上的结果广告多、版本乱、没有译文注释。诗迹山河把 32 万首古诗词放进云端数据库，提供干净的搜索、译文、作者信息和收藏功能，手机浏览器打开就能用。

**展示动作**：打开公网首页，指着检查台三个绿灯——「后端、数据、收藏服务都是活的」。

## 第二段：核心流程（约 60 秒）

**说什么**：页面只有一个，数据全在云上。流程是——浏览器打开静态页 → 页面 JS 请求云函数 → 云函数查 PostgreSQL → 返回 JSON → 页面渲染。

**展示动作**（按顺序做）：
1. 页面加载后自动出现热门诗词榜（真实数据库数据，榜首《静夜思》人气 1 亿）
2. 指着检查台：health（服务活着）、hot（榜单有数据）、favorites（已有 N 首收藏）
3. 点开 F12 → 网络，刷新一次：请求地址都是 `service.tcloudbase.com` 公网接口，响应头里有 `Access-Control-Allow-Origin: *`（跨域放行的铁证）

## 第三段：提示词改写（约 45 秒）

**说什么**：这个项目是跟着 AI 用「提示词」一步步做出来的。举一个真实例子——

- ❌ 最初的模糊说法：「给我的网站加个收藏功能」
- ✅ 改写后的有效提示：「用 CloudBase 云函数实现收藏接口：POST /api/favorites 接收 poem_id 写入 favorites 表，防重复（应用层先查 + 数据库 UNIQUE 约束），响应统一 {ok, data, error} 三字段，带 CORS 头」

**点破原理**：改写的差别在于——说清了「接口路径、入参、表名、防重复策略、响应格式、跨域」六件事，AI 就不用猜了，一次成型。

## 第四段：验证方式（约 45 秒）

**说什么**：每个功能都要「眼见为实」，我的验证闭环是——

**展示动作**（现场做，每步有可核对的结果）：
1. **真实写入**：执行 `POST /api/favorites {"poem_id":8}` → 返回 200 和新记录 id
2. **读回验证**：刷新页面，收藏数 +1，列表里出现《赋得古原草送别》
3. **防重复**：再发一次同样请求 → 409「已收藏过这首诗」
4. **坏请求不崩**：发个乱码 body → 400 中文提示，页面和接口都活着
