## 第一段：用户问题（约 40 秒）

**说什么**：网上查古诗，广告多、版本乱、没译文。诗迹山河把古诗数据放进云端 PostgreSQL（poets/poems/favorites 三表），提供干净的搜索、译文注释和收藏功能，浏览器打开即用。

**展示动作**：打开公网首页，指检查台三个绿灯——服务、数据、收藏都是活的。

## 第二段：核心流程 —— 含一次真实写入 + 刷新持久化（约 90 秒）

**说什么**：页面只是壳，数据全在云上。流程：浏览器静态页 → JS 调公网云函数 → 查 PostgreSQL → 返回 JSON → 渲染。

**展示动作**（按顺序做，每步有可见结果）：
1. 页面加载，热门榜出现真实数据（榜首《静夜思》，人气 1 亿）
2. **真实写入**：现场执行 `POST /api/favorites {"poem_id":9}`（黄鹤楼）→ 返回 200 和新记录 id
3. **刷新持久化**：**Ctrl+F5 刷新页面** → 检查台 favorites 数量 +1，列表出现《黄鹤楼》——刷新后不消失，因为数据真的落库了，不在页面里
4. F12 → 网络 → 点接口请求：地址是 `service.tcloudbase.com`（公网），响应头有 `Access-Control-Allow-Origin: *`（跨域放行）

## 第三段：提示词改写过程（约 60 秒）

**说什么**：这个项目是跟着 AI 用提示词做出来的，举一个真实改写例子——

- ❌ 模糊版：「给网站加个收藏功能」
- ✅ 有效版：「用 CloudBase 云函数实现 POST /api/favorites：接收 poem_id 写入 favorites 表；防重复两层（应用层先查后插 + 数据库 UNIQUE 约束）；响应统一 {ok, data, error}；带 CORS 头；错误用中文提示并区分 400/404/409」

**点破原理**：改写补齐了六件事——路径、入参、表名、防重复策略、响应格式、错误码。AI 不用猜，一次成型，源码（`cloudfunctions/api-favorites/index.js`）与这段提示词逐条对应。

## 第四段：验证方式（约 60 秒）

**说什么**：每个功能眼见为实，验证闭环四步：

1. **读**：`GET /api/hot?limit=1` → 返回库里真实榜首
2. **写**：上面第二段已现场 POST 成功并读回
