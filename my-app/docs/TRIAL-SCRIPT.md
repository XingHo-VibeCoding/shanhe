## 一、试用任务脚本（整段复制发给试用者）

设计说明（自己看，别发给对方）：只说"点什么"，不解释原理；**第 2 步和第 7 步故意写得含糊**，看 TA 能不能自己找到"每日荐诗"和"标记完成"按钮，找不到就是卡点。

---

【帮忙试用 3 分钟：一个背诗的小网站】

网址（手机或电脑浏览器打开都行）：
https://shiji-shanhe.app.workbuddy.host/

1. 打开上面的网址
2. 在首页找一首你觉得「今天值得背」的诗，记住它的名字
3. 打开网站里的「检查台」页面：
   https://shiji-shanhe.app.workbuddy.host/mock/index.html
4. 在页面下半部分，记一条你的打卡（诗随便挑一首）
5. 刷新一下页面，看看你刚记的那条还在不在
6. 把你刚记的那条，变成「已完成」的样子
7. 再把这条记录删掉

做的过程中，卡住了、看不懂了、点错了，随手说一声就行，说原话最好。谢谢！

## 三、拿到记录后怎么办（三步走）

### 第 1 步：选最高优先级卡点（判断标准，从上往下第一条命中就用）

1. **挡住主链路的**（第 4~7 步做不下去）最优先，UI 好不好看都靠边
2. **多人卡同一处**的，比单人卡的重要
3. **看不懂文案**的，比"按钮顺不顺手"的重要
4. 选不出来时，选**用时最长的那一步**

结论写成一行：`卡点：第 X 步，现象____，试用者原话"____"`

### 第 2 步：套修复提示词模板

```
【任务】修复诗迹山河的一个可用性问题（只改这一处，不加新功能、不大改样式）
【现象】试用者在第 X 步（做什么）卡住，原话："……"
【复现】设备：手机/电脑；打开 <页面 URL>；依次操作：<步骤列表>
【期望】试用者本该：……
【实际】试用者实际看到：……
【环境】线上地址 https://shiji-shanhe.app.workbuddy.host/，页面 <文件名>
【验收】手机宽度下，按"复验最小任务"重做第 X 步，不再卡住
```

### 第 3 步：修复后给试用者的最小复验任务

只发一条，控制在 1 分钟内（别让人家全套重做）：

> 上次你卡住的地方改好了，麻烦帮忙再做一下这一步就行：
> **<原样贴出卡住的那一步>**
> 做完告诉我顺不顺，还有哪里别扭。谢谢！

复验通过后，这次试用就算闭环；把复验结果记进第二张记录表的"备注"列。
