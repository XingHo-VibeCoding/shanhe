# 诗迹山河 · 结营复盘（Day 28）

> 每日一问：28 天里你最大的一个认知改变是什么？
> 我的答案：**用户的真实行为最打脸——我按想象做的产品，被一个外行 3 分钟就照出了原形。**

---

## 一、这件事的完整经过

结营前一周（Day 27），我请了一位没参与项目的真人试用诗迹山河，任务很简单：打开网站、找到一首李白的诗、看看详情、再自己搜一次。

我在旁边预设了所有"可能卡住"的地方：页面会不会太素、配色会不会看不清、详情页内容全不全。

结果 TA 卡住的方式我一个都没猜到——**TA 在搜索框里背了一句诗**：

- 「轻舟已过万重山」（运气好，外部接口兜底救了回来）
- 「三过平山堂下苏轼」（线上返回 0 首结果，页面空手而归）

我设计的是"关键词搜索"，用户带来的是"背出来的句子"。那一刻我意识到：**我自己永远测不出真实用法**——我太熟悉自己的产品了，熟悉到只会按设计者的路径点。

## 二、这个改变带来的做法（都已沉淀成文件）

| 沉淀 | 文件 | 一句话说明 |
|---|---|---|
| 试用任务单 | `docs/TRIAL-SCRIPT.md` | 只给目标不给操作指引，TA 怎么走才是真实数据 |
| 记录表模板 | 同上 | 卡住必记**原话**，不翻译成技术问题 |
| 故意含糊的两步 | 同上 | 第 2、7 步写得含糊，当"卡点探针"用 |
| 修复提示词模板 | 同上第三节 | 现象/复现/期望/约束/验收，五段写清楚 |
| 最小复验任务 | 同上 | 修复后只让试用者重做卡住的那一步，1 分钟闭环 |

Day 27 当天就按这套流程修了「整句兜底」：句中识别诗人名 + 内容片段匹配，线上实测「三过平山堂下苏轼」从 0 结果变成苏轼名篇。**这个修复不是我想出来的，是被用户的真实行为逼出来的。**

## 三、认知改变的辐射面

它连着改变了我其他几件事的看法：

1. **验收观**：验收表里"反馈交互"一项，不再是我说"交互存在"就算，而是真人在真机上实测（Day 28 用探针跑出联想 30 元素、标红 23 处）。
2. **测试观**：我自己测一百遍，不如外行测一遍；所以"邀请第三方试用"从可选项变成了必做板块。
3. **需求观**：用户嘴上说的（"帮我做个搜索"）和手上做的（背整句来搜）是两回事，产品要跟着手上做的走。

## 四、200 字以内结营总结

28 天做了「诗迹山河」：一个能搜、能看懂、能打卡的古诗学习站。32.6 万首本地诗库 + 四个云函数上线公网，v1.0 已打标发布，回滚演练实测退 73 秒、恢复 55 秒。最大的收获不是代码，是流程：发布前五项体检、真实回滚、外行试用与提示词模板。最打脸的一课来自真人试用——用户背整句搜诗，暴露了我从没想过的问题，也让我记住：验证靠机器和真人，不靠感觉。
