# 诗迹山河 · 结营演示提纲（3~5 分钟）

> 现场演示全部走线上正式版：https://shiji-shanhe.app.workbuddy.host/
> 讲稿按 6 段走，总共约 4 分半；每段标了时间，超时就砍第 5 段细节。

---

## 1. 用户问题（约 30 秒）

想认真背古诗的人有三个痛点：

1. **搜不到**：只会背一句诗，或者只会打"那首王维的九月九"，普通搜索给不了结果
2. **看不懂**：找到了也只有原文，没译文没注释，等于没背
3. **没记录**：背没背、背了几首，没有任何地方记账

诗迹山河就是冲这三个痛点做的：一个能搜、能看懂、能打卡的古诗学习站。

## 2. 核心流程（约 90 秒，边讲边操作）

| 顺序 | 操作（URL 都在公网） | 展示点 |
|---|---|---|
| ① | 打开首页 | 每日荐诗、精选卡片（不用注册，打开就能用） |
| ② | 搜索框输入「三过平山堂下苏轼」 | **整句也能搜**：自动识别出苏轼，落到他的名篇（Day 27 修复） |
| ③ | 换成搜「月」 | 关键词朱砂标红、相关诗人延伸条、搜索历史 |
| ④ | 点开《九月九日忆山东兄弟》详情页 | 原文/译文/注释/背景/赏析五件套齐全 |
| ⑤ | 诗人足迹页 | 苏轼一生足迹地图（山体阴影 + 朝代时间轴） |
| ⑥ | 检查台（/mock/index.html） | 选诗 → 「＋ 打卡」→ 刷新还在 → 「标记完成」→ 删除（二次确认） |

## 3. 提示词改写（约 60 秒，讲方法）

28 天全程 vibe coding：我说**意图和现象**，AI 出代码，我负责验证。

举 Day 27 的真实例子——试用者背整句来搜，搜了个寂寞：

- ❌ 差提示词："把搜索做好一点"
- ✅ 好提示词（按模板写的）：
  > 【现象】试用者输入「三过平山堂下苏轼」返回 0 结果，原话"搜不出来"
  > 【复现】打开搜索页 → 输入整句 → 点搜索
  > 【期望】能找到苏轼或含这句的诗
  > 【约束】不加新功能，手机端也要可用
- AI 由此给出"句中识别诗人名 + 内容片段匹配"的整句兜底，上线实测 0 结果 → 苏轼名篇

模板沉淀在 `docs/TRIAL-SCRIPT.md`，谁都能复用。

## 4. 验证方式（约 45 秒）

不靠"我觉得没问题"，靠四道关：

1. **发布前检查脚本**（Day 25 做的）：密钥泄露 / .env 防护 / 公网可达 / API 健康 / 资源引用，5 项一键体检
2. **最终验收表**（`docs/FINAL-ACCEPTANCE.md`）：10 项逐项 PASS + 实测证据，0 FAIL
3. **两轮重复检测**：打卡增删改查连跑两遍全绿（防偶发）
4. **真实回滚演练**（Day 26）：线上真的退回过旧版又恢复，回退 73 秒、恢复 55 秒

## 5. 平台限制（约 45 秒，诚实交代）

1. **万维易源免费额度剩约 5 天**：搜索最后一级兜底用它，耗尽后兜底失效——但 Day 27 修复后搜索大多走本地库，核心功能不受影响
2. **SiliconFlow 余额查询接口已下线**：余额只能上控制台看，不影响调用本身
3. **git 推送 ≠ 线上更新**：部署是独立动作，漏一步线上就是旧版（Day 15-18 踩过）
4. 数据覆盖有短板：32.6 万首里仅约 4279 首带译文，还在用大模型批量补

## 6. 后续优化计划（约 30 秒）

按优先级：

1. 检查台加正式入口（现在藏得深，试用者要靠链接才能找到）
2. 数据导出按钮 + 打卡完成率统计（检查台页内）
3. 译文覆盖率 4279 → 1 万+
4. 清理数据源里 68 个两字截断作者名（如「赵必」）
5. 回滚手册里"云函数回退、数据恢复"两条备查路径做实操演练
